# План рефакторинга: «значения — формулы; состояние и эффекты — скоупу»

> **Статус (июль 2026): ВЫПОЛНЕН.** Все шесть фаз + независимый трек
> реализованы одной веткой `refactor/wire-two-laws` (решение владельца).
> Отклонения от плана: жнец удалён целиком, а не оставлен dev-детектором
> (детектор утечек — в бэклог); eslint-правило `require-retain`
> перепрофилировано в `state-needs-scope`; расширение фаззера
> switch-узлами перенесено из фазы 4 в фазу 6 (до фикса семантики
> одновременности оно давало бы ложные красные). Все пять известных
> нарушений законов — обычные проходящие тесты фаззера.

Целевая архитектура описывается двумя фразами:

1. **Значения — формулы.** Чистые производные подключаются по спросу, спят без
   слушателей, собираются GC. Живость не угадывается никем.
2. **Состояние и эффекты принадлежат скоупу.** `hold`/`accum`/`perform` — это
   «ячейка + процесс», зарегистрированный у владельца. Время жизни объявлено
   в коде, а не выведено эвристикой.

Плюс два закона движка, записанные как исполняемые инварианты:

- **push ≡ pull** — на границе каждого момента доставленное слушателям равно
  `sample()`;
- **abort = no-trace** — брошенный момент бесследен для любого состояния,
  включая внутренние кэши движка.

Метрика успеха: механизмов жизненного цикла 5 → 2 (спрос для формул, скоуп
для состояния/эффектов); отрицательный дифф LOC в лайфцикл-коде; каждый
инвариант — оракул фаззера, а не абзац в доке.

Рабочий процесс: TDD, ветка → PR → мержит владелец репо, ru-зеркала доков,
рост size-limit — осознанным решением в тексте PR.

## Фаза 0 — Фаззер + законы (сетка безопасности)

**Ветка:** `test/frp-fuzzer`. Ничего не меняет в ядре.

Генератор случайных графов (все комбинаторы) и случайных последовательностей
операций (`set`/`fire`/`batch`/`listen`/`unlisten`/`dispose`/бросающий
колбэк). Четыре оракула:

1. **push ≡ pull** — после каждого момента;
2. **abort = no-trace** — граф-близнец: одному даём бросающую операцию,
   другому нет, после аборта они обязаны совпадать;
3. **cold ≡ warm** — `sample()` холодной цепочки равен `sample()` той же
   цепочки со слушателем;
4. **сон = отцепка** — после ухода всех слушателей чистая цепочка не
   держится источником.

Лёгкий режим (N сидов) в CI, глубокий — в stress-наборе. Известные баги
(отравление eq-skip при аборте, пересев lift в теле batch, switchB
push/pull, промежуточные `hold.updates`) фиксируются как воспроизводящие
сиды со `skip` и ссылкой на фазу, где чинятся. Оба закона — в FRP-MODEL.md.

**Приёмка:** фаззер воспроизводит все известные баги; новые находки
пополняют списки фаз 5–6 до старта рефакторинга.

## Фаза 1 — API-поверхность: Wire + декларативные комбинаторы

**Ветка:** `feat/wire-api`. Только переименования и сахар, ядро не меняется.
Старые имена — депрекейтнутые алиасы до 1.0 (механика Event → Stream).

**Переименование типа:** `Behavior` → **`Wire`** («провод»: биндинг —
подключение, спрос — ток течёт, только если что-то подключено). Метафора
объясняет и ленивую активацию.

**Данные вперёд, имена — намерениями:**

| Было                                          | Стало                                             |
| --------------------------------------------- | ------------------------------------------------- |
| `Behavior.lift2(f, a, b)` / `lift3` / `apply` | `combine(a, b, f)` — вариадик, арности умирают    |
| `submits.snapshot(draft, f)`                  | `draft.at(submits)` / `draft.at(submits, f)`      |
| `clicks.gate(enabled)`                        | `clicks.when(enabled)`                            |
| `Behavior.switchB(bb)` / `switchE`            | `flatten(w)`                                      |
| `ea.orElse(eb)`                               | `ea.or(eb)`                                       |
| `newBehavior(init)`                           | `wire(init)` — источник-ячейка с `.set`           |
| `newStream()`                                 | `stream()` — источник с `.fire` (кортежи умирают) |

Уровень 3 (авто-трекинг `derive(() => ...)`) — **сознательно отложен** в
бэклог: требует динамических зависимостей в движке; возможная надстройка
после завершения плана, под фаззером.

Миграция: доки en+ru, глоссарий («Wire — реактивное значение; в
FRP-литературе Behavior»), examples, шаблон create-continuum, AGENTS.md.

**Приёмка:** весь набор зелёный на алиасах и на новых именах; все доки и
примеры говорят на новом языке; дальнейшие фазы пишутся только в нём.

## Фаза 2 — Скоуп в ядре (инфраструктура, поведение не меняется)

**Ветка:** `feat/core-scope`.

В frp появляется минимальный `Scope` (cleanups, parent/children, dispose),
ambient `currentScope`, `root()`/`runInScope`. Owner в dom пересаживается на
него (mounts/contexts остаются dom-надстройкой).

**Приёмка:** весь набор зелёный без правок ожиданий тестов; рост бюджета
frp — явным решением в PR.

## Фаза 3 — Состояние и эффекты — владельцу + wire().on() (главная, breaking)

**Ветка:** `feat/owned-state`.

- `wire(init)` перестраивается в честную ячейку-источник (без
  hold-как-производной внутри).
- `hold`/`accum` → сахар: ячейка + процесс в `currentScope`; вне скоупа —
  обучающая ошибка, для модульного состояния — явный `root()`.
- **Декларативные переходы состояния** — публичное лицо владения:

  ```ts
  const count = wire(0)
    .on(inc, (n) => n + 1)
    .on(dec, (n) => n - 1)
    .on(reset, () => 0);
  ```

  Аргументы в порядке редьюсера `(state, event)`; `.on` регистрирует процесс
  в текущем скоупе. Танец merge+accum с ручным языком событий умирает.

- `perform` → та же регистрация в скоупе.
- **Удаляются:** dispose-каскад из `listen()`/`subscribe()`, жнец
  (FinalizationRegistry остаётся только dev-детектором утечек),
  «disposed»-ловушки. `retain()` — чисто перф-подсказка.
- Пробы аудита №4 (замороженный hold, потерянная история accum) — красные
  TDD-тесты фазы.
- Ченджсет — breaking minor с migration-заметкой.

**Приёмка:** «hold умирает при отписке» невозможен; оракулы 1, 3, 4 зелёные
на всех сидах; heap-стрессы проходят без жнеца.

## Фаза 4 — Оставшиеся eager-узлы → формулы

**Ветка:** `feat/formula-switch`. Изолирована из-за риска: switch —
исторически самый багоносный узел.

`distinct`/`once`/`flatten` (бывшие switchE/switchB) переводятся на рецепты:
подключение по спросу, память сбрасывается/пересеивается на wake (`once`-флаг
персистентен — он консистентен с наблюдаемой историей; у `distinct` память
«на тёплый период», документируется).

**Приёмка:** eager-leak класс закрыт целиком; фаззер с расширенным
генератором (sleep/wake-циклы вокруг flatten) зелёный.

## Фаза 5 — Атомарность момента

**Ветка:** `fix/moment-atomicity`.

Идиома стейджинга (как у hold) — на внутренние переменные движка: eq-skip
`current` в ячейке, кэши `combine` (включая отравление при аборте), пересев
при wake-в-теле-батча. Сиды из фазы 0 снимаются со `skip`.

**Приёмка:** оракул 2 зелёный на всех сидах; бенч горячего пути combine без
регрессии.

## Фаза 6 — Семантика одновременности

**Ветка:** `fix/moment-semantics`.

Промежуточные значения `updates` внутри одного момента и push/pull-расхождение
flatten при одновременном переключении+обновлении. Сначала семантика
записывается в FRP-MODEL (одно коалесцированное вхождение на границе), потом
реализация под фаззером.

**Приёмка:** оракул 1 зелёный на сидах flatten/updates; доки транзакций
дополнены.

## Независимый трек — мелочь, параллельно любой фазе

`resource` в std (стейл error затирает ok + sync-throw — самый горячий для
приложений); `distinctB` в dom на `source()`+`onWake` (утечка `when`/`Show`);
style-diff исчезнувших ключей; фаст-пас `sample()` (~8×); гвард
`onClick={Wire}`; проверка RANK_LIMIT при конструировании.
