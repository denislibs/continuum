## Попробовать — прямо здесь

<script setup>
const heroCounter = `import { state } from '@continuum-js/frp';

export default function Counter() {
  const count = state(0);
  // Counter больше не выполнится. {count} привязывает один текстовый
  // узел; клик патчит ровно его — без ре-рендера.
  return (
    <button onClick={() => count.update((n) => n + 1)}>
      count: {count}
    </button>
  );
}`;
</script>

<ClientOnly>
  <Playground height="300px" :code="heroCounter" />
</ClientOnly>

Поменяйте код, нажмите **Run**, откройте вкладку **Compiled** — и увидите, в
какой быстрый код это превращается. Или создайте свой проект:

```bash
npm create continuum-js@latest my-app
```

Знаете `useState` — считайте, уже умеете. Разница одна: компонент `Counter`
выполняется только раз. `{count}` — это привязка к значению; по клику
меняется ровно этот текст на странице, без перерисовки.

## А ещё — то, чего нет у React и Solid

Обычно undo, автосохранение, синхронизация между вкладками и поиск без гонок —
это отдельная библиотека под каждую задачу. В Continuum все действия
пользователя идут через одно место, поэтому такие фичи добавляются буквально
парой строк:

```tsx
const actions = stream<Action>();

const todos = actions.accum([], reduce); // сам список дел
const history = actions.accum(emptyHistory, undoReduce); // + отмена (undo)
onCleanup(persist("todos", todos)); //                     + сохранение
// то же событие из другой вкладки:                        + синхронизация
```

Поиск не путает ответы: старый ответ сервера не может перезаписать новый —
об этом заботится сама библиотека:

```tsx
const results = resource(debounce(query.updates, 300), search);
```

Логика обработки при этом не меняется. Готовые рецепты — undo, оптимистичные
обновления, поиск без гонок — в [сборнике паттернов](/ru/guides/patterns).
