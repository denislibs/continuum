## Попробовать — прямо здесь

<script setup>
const heroCounter = `import { state } from '@continuum-js/frp';

export default function Counter() {
  const count = state(0);
  // Counter больше не выполнится. {count} привязывает один текстовый
  // узел; клик патчит ровно его — без ре-рендера.
  return (
    <button onClick={() => count.update((n) => n + 1)}>
      count: {count}
    </button>
  );
}`;
</script>

<ClientOnly>
  <Playground height="300px" :code="heroCounter" />
</ClientOnly>

Поменяйте код, нажмите **Run**, откройте вкладку **Compiled** — увидите, как
он превращается в шаблон, разбираемый один раз, с единственной дыркой-вставкой.
Затем создайте свой проект:

```bash
npm create continuum-js@latest my-app
```

Если вы знаете `useState`, вы уже знаете и это — с одной разницей:
`Counter` больше никогда не выполнится. `{count}` привязывает текстовый узел
к значению; клик патчит ровно этот узел.

## А дальше — то, чего нет у других

Всё, что выше, обещает и Solid. Вот часть, которой у него нет: **само
изменение — это значение.** Проведите каждое изменение через один поток
действий и сверните его — и фичи, на которые обычно берут по библиотеке,
становятся одной строкой каждая:

```tsx
const actions = stream<Action>();

const todos = actions.accum(loadPersisted("todos", []), reduce); // состояние
const history = actions.accum(emptyHistory, undoReduce); //       + undo
onCleanup(persist("todos", todos)); //                            + персист
// событие `storage`, диспатчащее в тот же редьюсер:              + синхронизация вкладок
```

А поскольку запросы — тоже поток, поиск не умеет гоняться:

```tsx
const results = resource(debounce(query.updates, 300), search);
// устаревший ответ физически не может перезаписать свежий
```

Редьюсер при этом не меняется ни на букву. [Книга
паттернов](/ru/guides/patterns) проходит всё это — undo, оптимистичные
обновления, поиск без гонок — по несколько строк поверх одного потока.
