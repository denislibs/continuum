# Состояние и производные значения

## Два способа завести состояние

**`newBehavior`** — когда состоянием управляют извне (императивный сеттер):

```ts
import { newBehavior } from "@continuum-js/frp";

const [theme, setTheme] = newBehavior<"light" | "dark">("light");
```

**`newEvent` + `accum`** — когда состояние — это свёртка происходящего:

```ts
import { newEvent } from "@continuum-js/frp";

const [clicks, fire] = newEvent<MouseEvent>();
const count = clicks.accum(0, (_e, n) => n + 1);
```

Второй способ предпочтителен, когда есть явный поток причин: он делает
историю состояния читаемой («count — это число кликов»), а не размазанной по
вызовам сеттера. `setX` из `newBehavior` — это люк для мест, где событие
неоткуда взять (инициализация, интеграция с внешним кодом).

## Производные значения — только `map`/`lift`

Всё, что можно вычислить из существующих Behaviors, **не должно храниться**:

```ts
import { Behavior } from "@continuum-js/frp";

const total = items.map((xs) => xs.reduce((s, i) => s + i.price, 0));
const label = Behavior.lift2(
  (t, cur) => `${t.toFixed(2)} ${cur}`,
  total,
  currency,
);
```

Анти-паттерн — «вычислить и положить сеттером»:

```ts
// ПЛОХО: total теперь нужно не забывать обновлять при каждом изменении items
const [total, setTotal] = newBehavior(0);
itemsChanged.listen(() => setTotal(computeTotal()));
```

Это ручная синхронизация — ровно то, от чего FRP избавляет. Правило: если
значение выводимо — оно `map`; `newBehavior` только для первичных фактов.

## Чтение текущего значения

- В JSX Behavior кладётся как есть — `{count}` — это привязка.
- В обработчике события используйте `snapshot`, а не `sample`:

```ts
const submitted = submitClicks.snapshot(draft, (_e, text) => text);
```

`b.sample()` существует и честно возвращает текущее значение, но у него нет
семантики одновременности: два одновременных события увидят «какое-то»
значение в зависимости от порядка. `snapshot` определён точно: значение _до_
текущего момента. Практическое правило: `sample` — для кода вне сети
(инициализация, тесты, интеграции), `snapshot` — внутри неё.

## Подавление лишних обновлений

`distinctB` из `@continuum-js/std` убирает подряд идущие равные значения —
полезно перед `dyn`/`Show`, чтобы не перестраивать поддерево зря:

```ts
import { distinctB } from "@continuum-js/std";

const page = distinctB(location().map((u) => u.pathname.split("/")[1]));
```

## Состояние вне компонентов

Behaviors — обычные объекты: их можно объявлять на уровне модуля и
импортировать. Так устроен `location()` в роутере — синглтон-Behavior на всю
страницу. Локальное состояние компонента живёт в его теле и умирает вместе с
поддеревом (см. гайд про владение).
