# Компилятор (опциональный)

Continuum работает без единого билд-плагина: JSX проходит стандартный
esbuild-трансформ, DOM строит рантайм-фактори. Это остаётся дефолтом —
любой vite/esbuild, ноль настройки.

`@continuum-js/vite-plugin` — **опциональный ускоритель** для
create-тяжёлых экранов (длинные списки, большие таблицы). Он компилирует
ровно тот JSX, который вы уже пишете, в клонируемые шаблоны: вся статика
склеивается в одну HTML-строку, распарсенную один раз на call-site, и
создание поддерева превращается в один `cloneNode(true)` плюс привязки
динамических «дырок» — техника, стоящая за цифрами Solid.

```bash
npm i -D @continuum-js/vite-plugin
```

```ts
// vite.config.ts
import { defineConfig } from "vite";
import continuum from "@continuum-js/vite-plugin";

export default defineConfig({
  plugins: [continuum()],
});
```

Это вся миграция: **код не меняется**. Семантика идентична — скомпилированный
выход привязывает провода, события и детей через те же внутренности, что и
рантайм-фактори (CI гоняет весь dom-набор тестов обоими путями). Всё, в чём
компилятор не уверен статически — спреды на элементах, динамические имена
тегов, SVG, — просто остаётся рантайм-фактори, так что корректность никогда
не зависит от ума компилятора.

Что это даёт (таблица js-framework-benchmark, script-время, одна машина):
создание 1k строк ~1,5× быстрее, добавление 1k ~1,6× быстрее, создание
10k ~1,5×; update-операции и без него в порядке.

Когда заморачиваться: приложения, создающие тысячи DOM-узлов за раз.
Обычное формы-и-дашборды приложение разницы не почувствует — пропустите
плагин и оставьте тулчейн без конфигурации.
