# Транзакции и время

Каждое обновление в Continuum происходит внутри **транзакции** — одного
атомарного момента логического времени. `e.fire(x)` открывает момент; всё,
что следует из `x`, устаканивается внутри него; момент закрывается; только
после этого эффекты (`listen`, патчи DOM) видят результат.

## Отсутствие глитчей

Если одно событие питает две ветки, которые позже сходятся («ромб»), точка
слияния пересчитывается **один раз за момент**, видя обе ветки обновлёнными:

```ts
const doubled = count.map((n) => n * 2);
const squared = count.map((n) => n * n);
const sum = combine(doubled, squared, (d, s) => d + s);
// count: 2 → 3 переводит sum 8 → 15 одним шагом. «6 + 4» не существует.
```

Внутри узлы ранжированы по глубине графа и обрабатываются в порядке рангов,
так что узел не сработает раньше, чем устаканятся его входы. Вы этим не
управляете — это и есть смысл слова «транзакция» здесь.

## Одновременность — настоящая

Два вхождения в одном моменте _действительно одновременны_, и API заставляет
сказать, что это значит:

- `Stream.merge(ea, eb, combine)` — одновременные вхождения коалесцируются
  функцией `combine`, а не упорядочиваются как попало;
- `at` видит States _на начало момента_.

## Задержка `hold`

`hold`/`accum` обновляют States **на границе момента**. Внутри
транзакции, доставившей вхождение, State ещё показывает предыдущее
значение:

```ts
const count = root(() => clicks.accum(0, (_e, n) => n + 1)); // модульному состоянию нужен владелец
const before = count.at(clicks);
// на 3-м клике `before` равно 2 — значение ДО этого момента
```

Именно это делает рекурсивные определения корректными: «новое значение
зависит от старого» требует «старого», стабильного внутри момента. Прошлое
доступно; настоящее ещё формируется.

## Пакет из нескольких fire

Каждый `fire`/`set` обычно открывает собственный момент. Когда одно действие
пользователя обновляет несколько источников, оберните их в `batch` — всё
внутри войдёт в **один** момент: узлы-соединения пересчитаются один раз,
merge скоалесцирует, привязки запишут в DOM один раз:

```ts
import { batch } from "@continuum-js/frp";

batch(() => {
  query.set("");
  page.set(1);
  selection.set(null);
}); // один момент: один пересчёт на соединение, один патч DOM на привязку
```

Вложенный `batch` присоединяется к объемлющему моменту. Нужен он редко —
выведенное состояние обычно избавляет от необходимости сеттить несколько
источников разом, — но когда сеттите несколько, `batch` не даёт промежуточным
состояниям существовать вовсе.

Одно правило: у потока **не больше одного вхождения за момент**, поэтому
двойной `fire` _одного и того же_ потока внутри batch бросает ошибку (молча
свернуть второе вхождение поверх до-моментного состояния — значит испортить
`accum`). Повторный `set` одного _state_ легален — побеждает последняя
запись, а `updates` доставит подписчикам **одно** коалесцированное вхождение
с финальным значением.

## Наблюдатели — в кадровом проходе

Момент закрывается до возврата из `set()`: граф обновлён, `sample()`
актуален. Но наблюдатели выполняются не внутри момента, а **одним проходом
на кадр анимации**, в три шага:

1. **measures** — чтения layout, поставленные через `requestMeasure`, до
   любой записи;
2. **bindings** — DOM-привязки и `State.listen`. State — это _уровень_,
   поэтому привязка получает **одну** доставку на кадр с последним значением:
   десять обновлений между кадрами — одна запись в DOM и одна перестройка
   региона, без всякого `batch`;
3. **effects** — `Stream.listen`, запросы `perform`, `persist`. Stream — это
   последовательность _происшествий_, поэтому эффект получает каждое, по
   порядку.

Если обработчик в проходе порождает новое событие (редирект роутера, ответ
`perform`), оно открывает **новый** момент, чьи наблюдатели попадают в тот же
проход — транзакции не вкладываются и не переплетаются. Наблюдатель,
отписанный до своей очереди, не вызывается: в уничтоженный регион никогда не
пишут кадром позже.

Код, которому нужно прочитать DOM сразу после записи — сфокусировать поле
только что открытого диалога, или тест — выполняет проход сам:

```ts
import { flushFrame } from "@continuum-js/frp";

open.set(true);
flushFrame(); // привязки отработали: диалог уже в DOM
dialog.querySelector("input")!.focus();
```

Хелперы `@continuum-js/test` (`click`, `type`, `fire`, `flush`) делают это
за вас.

о Sodium — в
