# Транзакции и время

Каждое обновление в Continuum происходит внутри **транзакции** — одного
атомарного момента логического времени. `fire(x)` открывает момент; всё, что
следует из `x`, устаканивается внутри него; момент закрывается; только после
этого эффекты (`listen`, патчи DOM) видят результат.

## Отсутствие глитчей

Если одно событие питает две ветки, которые позже сходятся («ромб»), точка
слияния пересчитывается **один раз за момент**, видя обе ветки обновлёнными:

```ts
const doubled = count.map((n) => n * 2);
const squared = count.map((n) => n * n);
const sum = Behavior.lift2((d, s) => d + s, doubled, squared);
// count: 2 → 3 переводит sum 8 → 15 одним шагом. «6 + 4» не существует.
```

Внутри узлы ранжированы по глубине графа и обрабатываются в порядке рангов,
так что узел не сработает раньше, чем устаканятся его входы. Вы этим не
управляете — это и есть смысл слова «транзакция» здесь.

## Одновременность — настоящая

Два вхождения в одном моменте _действительно одновременны_, и API заставляет
сказать, что это значит:

- `Event.merge(ea, eb, combine)` — одновременные вхождения коалесцируются
  функцией `combine`, а не упорядочиваются как попало;
- `snapshot` видит Behaviors _на начало момента_.

## Задержка `hold`

`hold`/`accum` обновляют Behaviors **на границе момента**. Внутри
транзакции, доставившей вхождение, Behavior ещё показывает предыдущее
значение:

```ts
const count = clicks.accum(0, (_e, n) => n + 1);
const before = clicks.snapshot(count, (_e, n) => n);
// на 3-м клике `before` равно 2 — значение ДО этого момента
```

Именно это делает рекурсивные определения корректными: «новое значение
зависит от старого» требует «старого», стабильного внутри момента. Прошлое
доступно; настоящее ещё формируется.

## Эффекты — после

Обработчики `listen` выполняются в фазе _post_, после закрытия момента. Если
обработчик порождает новое событие (редирект роутера, ответ `perform`), оно
открывает **новый** момент — транзакции не вкладываются и не переплетаются.

Полный операционный разбор — три фазы, ранги, `switch` и соответствие книге
о Sodium — в
[FRP-MODEL](https://github.com/denislibs/continuum/blob/main/FRP-MODEL.md).
