# Компоненты

Компонент — обычная функция, возвращающая DOM. Она выполняется **ровно один
раз** на каждое появление в дереве — это _конструктор живого поддерева_, а
не функция рендера.

```tsx
function Greeting(props: { name: Behavior<string> }) {
  return <p>Привет, {props.name}!</p>;
}
```

Нет ни инстанса, ни объекта жизненного цикла, ни повторных вызовов. Всё, что
компонент настроил — привязки, подписки, таймеры, — живёт до уничтожения его
поддерева (см. [Владение](/ru/concepts/ownership)).

## Пропсы

Пропсы читаются один раз, в теле. Конвенция, которая держит компоненты
честными:

- **меняется во времени** → принимайте `Behavior<T>`;
- **фиксировано на всю жизнь поддерева** → принимайте просто `T`.

```tsx
function Price(props: { amount: Behavior<number>; currency: string }) {
  return (
    <span>
      {props.amount.map((a) => a.toFixed(2))} {props.currency}
    </span>
  );
}
```

Механизма «пропсы изменились» нет: если родитель хочет менять то, что
показывает ребёнок, он передаёт ему Behavior. Деструктурировать пропсы
безопасно — это обычные значения.

## Дети

`children` — всё, что JSX туда положил: узлы, строки, Behaviors, массивы или
функция (render prop), если компоненту так удобнее:

```tsx
function Card(props: { title: string; children?: Child }) {
  return (
    <section class="card">
      <h3>{props.title}</h3>
      {props.children}
    </section>
  );
}
```

## Элементы — это значения

JSX немедленно вычисляется в настоящие DOM-узлы. Паттерны, требующие ref в
React, здесь тривиальны:

```tsx
const input = (<input />) as HTMLInputElement;
onMount(() => input.focus());
return <form>{input}</form>;
```

Для элементов глубоко в JSX есть `ref={fn}` / `ref={obj}` — срабатывает при
создании.

## Никаких правил

Ничего не перезапускается, поэтому хелперы компонентов — обычные функции.
Создавайте состояние в условии, в цикле, на уровне модуля; выносите
«кастомные хуки» как функции, возвращающие Behaviors/Events — без правил
порядка и линт-плагинов.
