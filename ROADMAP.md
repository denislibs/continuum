# Дорожная карта Continuum

Стратегия развития от «работающего исследовательского фреймворка» к «фреймворку,
которым пользуются в реальных проектах». Версии условные: каждая веха — это
согласованный набор возможностей, а не календарный срок.

Текущее состояние (v0.2): ядро FRP (транзакции, ранги, коалесинг), рендерер
(fine-grained привязки, `each` с LIS, владение, контекст, jsx-runtime),
`@continuum-js/std` (resource, debounce, …), непрерывное время
(`integral`/`derivative`/`warp`), 5 примеров, бенчмарк js-framework-benchmark,
бюджеты size-limit, CI.

Легенда: 🔴 блокер для следующих вех · 🟡 важно · 🟢 желательно

## v0.3 — «Продукт, а не репозиторий» (публикация и DX)

Цель: `npm create continuum` → работающее приложение за минуту. Пока пакеты
нельзя поставить извне монорепо, всё остальное — теория.

### 🔴 Сборка dist и публикация в npm

Сейчас пакеты отдают TypeScript-исходники (`main: ./src/index.ts`) — это
работает только внутри workspace с общим tsconfig.

- [x] Сборка каждого пакета в `dist/` (ESM + `.d.ts`) — plain `tsc` с
      `tsconfig.build.json` (module-preserving, без бандлера; внутренние
      импорты с `.js`-расширениями — dist валиден и для Node ESM);
- [x] `exports` maps на `dist/` с условиями `types`/`import`; поле
      `publishConfig`, `files: ["dist"]`; dev внутри монорепо — через
      `paths` в `tsconfig.base.json` (typecheck не требует dist);
- [x] у `@continuum-js/dom` собрать и субпути `jsx-runtime`/`jsx-dev-runtime`;
- [x] проверка «чистой установки»: `npm run smoke` — pack → установка
      тарболов в чистый Vite-проект → `tsc --noEmit` + `vite build` +
      импорт из Node;
- [ ] решить вопрос имени в npm (scope `@continuum` пуст — 0 пакетов в
      поиске; свободна ли организация, проверяется только после
      `npm login`);
- [ ] версионирование и changelog — `changesets` (работает с workspaces,
      автоматизирует связные бампы frp→dom→std);
- [ ] GitHub Action `release.yml`: публикация по тегу (это релизный конвейер,
      а не проверка на PR — замеры перформанса в CI по-прежнему не гоняем).

Критерий готовности: `npm i @continuum-js/dom` в пустом Vite-проекте — и счётчик
из README работает без правок tsconfig.

### 🔴 `create-continuum` — scaffold CLI

- [x] пакет `packages/create-continuum` (`create-continuum-js`, buildless
      ESM без зависимостей), запускается через
      `npm create continuum-js@latest my-app`;
- [x] шаблон: Vite + TS, `jsxImportSource: "@continuum-js/dom"`, готовый
      counter-компонент, vitest с jsdom;
- [x] минимум вопросов (имя проекта аргументом или интерактивно; выбор

- [x] e2e-тест: в `npm run smoke` CLI генерирует проект во временную папку,
      зависимости подменяются на локальные тарболы → `npm i` →
      `tsc --noEmit && vite build` → тест сгенерированного приложения.

### 🟡 Гигиена API перед публикацией

Публикация фиксирует контракт — дешевле навести порядок до неё.

- [x] аудит публичного API всех трёх пакетов: движковые методы
      (`rank`, `listen_`, `send_`, `ensureBiggerThan`, `Transaction.current`)
      помечены `@internal`; случайных экспортов не найдено;
- [x] JSDoc на каждый публичный символ (классы, типы, конструкторы
      источников — включая денотации у `Event`/`Behavior`);
- [x] единообразие имён: пары «функция ↔ компонент» (`when`/`Show`,
      `dyn`/`Dynamic`, `each`/`Each`, `portal`/`Portal`) задокументированы
      как осознанная симметрия в `packages/dom/src/index.tsx`;

## v0.4 — «На этом можно писать SPA» (роутер)

Цель: маршрутизация как первоклассный житель FRP-модели. URL — это буквально
`Behavior<Route>`; это самая выигрышная демонстрация подхода.

### 🔴 `@continuum-js/router`

- [ ] `location(): Behavior<URL>` поверх History API (popstate + перехват
      навигаций), `navigate(to)` — событийный вход;
- [ ] матчер путей: статические сегменты, параметры `:id`, wildcard,
      типизированные параметры на выходе (`Route<{ id: string }>`);
- [ ] `<Router>`/`<Route>` поверх `dyn`: смена маршрута = смена динамической
      области, владение уничтожает поддерево ушедшей страницы;
- [ ] вложенные маршруты и layout'ы (`<Outlet>`), контекст маршрута через
      имеющийся `createContext`;
- [ ] ленивые страницы: `lazy(() => import("./Page"))` поверх `resource` из
      std — состояния pending/failure бесплатно;
- [ ] `<Link>` с активным состоянием (`Behavior<boolean>`), scroll restoration;
- [ ] guard'ы/redirect как чистые функции `Route → Route | Redirect`;
- [ ] пример `examples/router-app`: страницы, вложенный layout, ленивая
      страница, 404.

Критерий готовности: todo-пример переписывается в многостраничное приложение
без хаков, back/forward браузера работает, утечек владения нет (тест).

### 🟡 Тест-утилиты `@continuum-js/test`

Понадобятся и нам (роутер тестировать), и пользователям.

- [ ] `render(view)` → `{ container, dispose }` с автоочисткой между тестами;
- [ ] `fire(el, event)` и хелперы ввода (`type`, `click`);
- [ ] `flush()` — дождаться завершения транзакций и фазы post (сейчас в тестах
      это ad-hoc `await new Promise(...)`);
- [ ] мок времени для `debounce`/`throttle`/`interval` (интеграция с
      vitest fake timers).

Цель: закрыть известные долги ядра, из-за которых сейчас нужны оговорки.

### 🔴 Изоляция ошибок рендерера (error boundaries)

- [ ] определить семантику: ошибка в `build`-фазе компонента и ошибка в

- [ ] `<Catch fallback={...}>`: ловит ошибку поддерева, уничтожает его

## Чем НЕ занимаемся (и почему)

- **Компилятор/билд-тайм-трансформ.** Ключевое решение фреймворка — Behavior
  как значение делает трансформ ненужным. Не отказываемся от него ради
  синтаксического сахара.
- **Сравнительные бенчмарки других фреймворков внутри репо.** Пробовали —
  честного сравнения в кустарной обвязке не получается (см. историю PR).
  Правильный путь — заявка в официальный krausest/js-framework-benchmark
  после публикации в npm (v0.3).
- **Совместимость с React-экосистемой хуков.** Модель принципиально другая;
  мимикрия под хуки размоет главную идею.

## Сквозные принципы

- Каждая веха заканчивается публикуемым релизом (после v0.3).
- Прогон бенчмарка локально до/после изменений ядра; бюджеты size-limit —
  жёсткие, расширение бюджета — осознанное решение в PR.
- TDD: красный тест раньше кода, включая воспроизведение багов.
- Новые возможности приходят с примером в `examples/` и страницей в доках
  (после v0.5).
