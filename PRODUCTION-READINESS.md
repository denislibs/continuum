# Аудит: чего не хватает до продакшн-реди

Дата аудита: 2026-07-07, состояние — v0.6 «Ядро без оговорок» закрыта,
опубликованы `@continuum-js/{frp,dom,std}@0.6.1`, `router@0.1.4`, `test@0.1.4`.

Рамка оценки. «Продакшн-реди» — это не «есть всё, что у Next.js». Это ответ
на вопросы тимлида, который решает, брать ли библиотеку в проект: _не
сломается ли, не брошена ли, смогу ли я отладить, что делать при обновлении,
закрывает ли она мои реальные задачи_. По этой рамке пробелы делятся на пять
групп — по убыванию критичности.

Легенда: 🔴 блокер · 🟡 важно · 🟢 по спросу

---

## 1. 🔴 Контракт стабильности — главный нетехнический блокер

Никто не ставит `0.x` в прод: по semver это «любой релиз может всё сломать».
Технически ядро готово к 1.0 (v0.6 закрыла все оговорки), но сам **контракт**
не оформлен:

- [ ] **Политика semver и депрекаций** — документ: что считается breaking,
      как API умирает (warning → мажор), сколько живут мажоры;
- [ ] **Матрица поддержки** — браузеры, ES-таргет, версии Node/TS/Vite.
      Сейчас нигде не написано, а первый вопрос энтерпрайза именно такой;
- [ ] **Гигиена репозитория**: в `.github/` только workflows. Нужны
      `SECURITY.md` (куда сообщать об уязвимости), `CONTRIBUTING.md`,
      шаблоны issue/PR;
- [ ] **npm provenance** (`--provenance` в release.yml) — галочка «собрано
      из этого репозитория» на странице пакета.

Самая дешёвая группа (порядка недели), и именно она отвечает на «не брошена ли».

## 2. 🔴 SSR и гидрация — главный технический блокер

Единственная большая функциональная дыра. Без `renderToString` нет SEO, нет
мета-фреймворков, нет «первого экрана мгновенно» — целый класс
продакшн-приложений отпадает на этапе выбора.

- [ ] `renderToString` — для точечного рендерера прямолинейнее, чем для
      VDOM: проход построения без браузерного DOM;
- [ ] гидрация — содержательно сложная часть: сопоставление существующих
      узлов привязкам без пересоздания, маркеры динамических областей;
- [ ] пример SSR-приложения в `examples/` + гайд в доках.

## 3. 🟡 Доказуемая надёжность в реальном браузере

Тестовая база сильная (200+ тестов, property-тесты fast-check, стресс на
утечки), но **вся она в jsdom**. Playwright в репо есть — только для
бенчмарка.

- [ ] **E2E-смоук в реальном Chromium**: собрать `examples/router-app`,
      прокликать навигацию/формы/back-forward. jsdom не ловит реальные
      фокус, скролл, history, layout;
- [ ] **Заявка в официальный krausest/js-framework-benchmark** — в роадмапе
      стояла «после публикации в npm», публикация давно случилась. Это
      одновременно перф-доказательство и заметность;
- [ ] **Задокументировать гарантию безопасности**: текст вставляется только
      через `createTextNode`, `innerHTML` в рендерере отсутствует — XSS
      через интерполяцию невозможен by construction. Пользователи это
      спрашивают, а у нас нигде не написано.

## 4. 🟡 Отлаживаемость и DX ежедневной работы

- [ ] **DevTools** — для FRP почти необходимость: когда у новичка «не
      обновляется», ему нужно _увидеть_ граф. У нас явный граф с рангами —
      визуализировать дешевле, чем кому-либо. Начать с dev-оверлея
      (инспектор узлов + лог транзакций), расширение браузера потом;
- [ ] **HMR**: интеграции с `import.meta.hot` нет — каждая правка это полная
      перезагрузка с потерей состояния. Минимум: честно задокументировать;
      максимум: hot-замена компонента с пересборкой поддерева;
- [ ] **Ошибки как учитель**: стандарт «ошибка говорит, что делать» (уже
      начат в disposed/rank) распространить на все броски ядра; возможно,
      пара eslint-правил под типовые грабли (`retain` для модульных
      производных).

## 5. 🟢 Экосистемный минимум (по спросу)

Продакшн-приложение — это формы и серверные данные:

- [ ] **`@continuum-js/forms`** — поле = `Behavior<T>`, валидность =
      производный `Behavior<Result>`; модель ложится идеально, лучшая
      витрина FRP;
- [ ] **`@continuum-js/query`** — кэш по ключу поверх `resource`,
      инвалидация, refetch on focus;
- [ ] **Interop-адаптеры** — Continuum-виджет внутри React-приложения:
      реалистичный путь миграции, никто не переписывает прод целиком;
- [ ] **Dogfood-приложение** — одно настоящее развёрнутое приложение
      (не todo): ответ на «кто этим пользуется?» и генератор реальных issue.

---

## Предлагаемый план: v0.7 «Можно брать в прод»

1. **Контракт 1.0** (semver-политика, матрица поддержки,
   SECURITY/CONTRIBUTING, provenance, страница про безопасность) —
   конвертирует уже сделанное в доверие немедленно;
2. **SSR + гидрация** — единственный настоящий инженерный вызов вехи;
3. **E2E в Chromium + заявка в krausest** — доказательства;
4. **DevTools-оверлей** — отлаживаемость;
5. → **1.0**; forms/query/interop — post-1.0 экосистема по реальному спросу.

Логика порядка: пункт 1 отвечает на вопросы доверия сразу; пункты 2–4
закрывают вопросы, которые задаст любой техлид на этапе выбора.
