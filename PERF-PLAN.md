# План оптимизации create-пути: «понятный JSX + компилятор, который делает его быстрым»

**Принцип (зафиксирован владельцем):** пользователь пишет обычный читаемый
JSX — единственный синтаксис вью. Никакого публичного `html`-тега, никакого
второго способа писать шаблоны. Скорость добывается опциональным
компилятором: без плагина JSX работает как сегодня (рантайм-фактори, любой
vite/esbuild без настройки), с плагином — компилируется в template+clone.
Тезис «тулчейн проще» остаётся правдой: плагин — ускоритель, не требование.

**Диагноз:** на update-операциях мы в одном классе с Solid; на create-heavy
проигрываем: рантайм строит DOM поэлементно (`createElement` × N +
`setAttribute` × M + `addEventListener` × K на строку списка). Solid берёт
своё четырьмя механизмами: клонирование шаблона, прямые пути к «дыркам»,
ноль рантайм-аллокаций на статику, делегирование событий.

**Метрика успеха:** create 1k / create 10k / append 1k в нашем харнессе —
в пределах ~1,2× от Solid на той же машине (JSX + плагин); update без
регрессий; main-entry `dom` не растёт сверх обоснованного; семантика
(Wire, скоупы, моменты, законы) не меняется — весь набор и фаззер зелёные.

---

## Фаза 0 — Бейзлайны: измерить реальный разрыв

Порт бенч-приложения на **Solid** (с их компилятором — честные цифры) и
**vanilla JS** (классическая krausest-реализация: template+clone +
делегирование) под тот же Playwright-харнесс; `bench.mjs` параметризуется
`BENCH_APP=continuum|solid|vanilla`. Одинаковая DOM-структура и селекторы.
Плюс грубый профиль нашего create-пути (что дороже: элементы, атрибуты,
слушатели, владение). Результат — `benchmark/BASELINES.md`.

**Приёмка:** три таблицы с одной машины; понятен вклад каждого
подозреваемого; последующие фазы сверяются с этим документом.

## Фаза 1 — Рантайм-диета (ускоряет весь существующий JSX)

- **Делегирование событий**: пузырящиеся (`click`, `input`, `keydown`, …)
  регистрируются один раз на document; хендлер лежит на элементе
  (`$$click`-свойство — умирает вместе с узлом, ноль cleanup-замыканий);
  `currentTarget` подменяется через `defineProperty` на время вызова;
  `stopPropagation` уважается. Неделегируемые (`focus`, `scroll`) — как
  раньше. Семантика фиксируется характеризационными тестами ДО правки;
  тесты с отсоединёнными контейнерами прикрепляются к document (делегация
  требует связности — как у Solid).
- **Аллокационная диета `h()`** — по фактам профиля фазы 0.
- **Ленивый Owner** — только если профиль покажет заметный вклад.

**Приёмка:** весь набор зелёный; замер против фазы 0; бюджет dom без
необоснованного роста.

## Фаза 2 — Внутренний template-рантайм + vite-плагин (гейт по цифрам)

**Гейт:** выполняется, только если после фазы 1 разрыв против Solid
остаётся практически значимым. Возможный честный итог — «делегирование
закрыло разрыв, компилятор не нужен»; тогда фаза закрывается решением.

1. **Внутренний рантайм «дырок»** — сабпат `@continuum-js/dom/compiled`
   (в паблик-доки не входит): `tmpl(html)` парсит строку один раз на модуль
   и возвращает клонер; `insert`/`bindAttr`/`bindProp` — те же привязки,
   что делает `h()` (Wire → listen в ambient-скоуп); `delegate` — из фазы 1.
   Прямые юнит-тесты как у обычного модуля — до и независимо от компилятора.
2. **`@continuum-js/vite-plugin`** — отдельный пакет, dev-зависимость
   (аналог `babel-plugin-jsx-dom-expressions`). Компилирует наш обычный JSX:
   статика склеивается в HTML-строку шаблона, динамика — дырки по заранее
   вычисленным путям (`firstChild.nextSibling…`); компоненты остаются
   вызовами функций; `<Show>`/`<Each>`/`dyn` вставляются через маркеры.
   **Честный фолбэк**: спред на элементе, динамический тег, всё непонятное
   статически — компилируется в сегодняшний `h()`; корректность никогда не
   зависит от ума компилятора.

**Приёмка:** тот же JSX-код бенча с плагином — Solid-класс по create;
двойной прогон тест-набора (с компиляцией и без) даёт одинаковые
результаты; смоук со скаффолдом+плагином; доки «Компилятор» en+ru; шаблон
CLI — опция (дефолт без плагина).

## Риски

- **Делегирование**: порядок хендлеров, re-entry, порталы (контент в
  `document.body` — связность есть), тесты с detached-узлами. Лечится
  характеризационными тестами до правки.
- **Компилятор**: контекстный парсинг (`<tr>` живёт только в `<table>` —
  грабли innerHTML, как решено в lit); никакой «умной полуподдержки» —
  либо уверен, либо фолбэк.
- **Двойной путь исполнения** — расхождение семантики; лечится двойным
  прогоном тестов в CI плагина.

## Бэклог за пределами плана

- Публичный `html`-тег поверх того же рантайма — только при реальном
  спросе на «быстро без билд-шага» (обратимое решение, ~день).
- SSR/гидрация — отдельная история.
