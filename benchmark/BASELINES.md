# Бейзлайны фазы 0 (PERF-PLAN)

Одна машина, один харнесс (`bench.mjs`, медиана 10 прогонов после 3
прогревов, Chromium/Playwright, замер click → painted через двойной rAF).
Запуск: `BENCH_APP=continuum|solid|vanilla npm run bench`.

Снято на ветке `perf/create-path` (базa — main после Wire-рефакторинга,
0.16.0). Solid — с их компилятором (vite-plugin-solid), vanilla —
классическая krausest-реализация (template+clone, делегирование на tbody).

| --------------------- | ------- | ------ | --------- | --------- |
| create rows (1k)      | 23.45   | 23.15  | 29.20     | **1.26×** |
| replace all (1k)      | 25.10   | 25.75  | 29.65     | 1.15×     |
| partial update (10th) | 10.85   | 17.80  | 19.00     | 1.07×     |

## Выводы (переворачивают исходную гипотезу плана)

1. **Create-разрыв реален, но умеренный**: 1.18–1.26× от Solid (не «в разы»).
   Атрибуция на строку таблицы у нас: ~7 `createElement` + ~5 `setAttribute`
   - 1 `addEventListener` + Owner строки + 2 живые привязки; у
     скомпилированных — 1 `cloneNode` + привязки.
2. **Настоящая аномалия — интерактивные операции над готовым списком**:
   swap 3×, remove 2.2×, select 1.33×. Все наши медианы там подозрительно
   равны одному кадру 60 Гц (15.75–16.10 мс), тогда как Solid/vanilla
   укладываются в текущий кадр (5–12 мс): наша работа выталкивает paint на
   следующий vsync.
3. **Подозреваемый №1 — восстановление фокуса в `each()`**: на КАЖДОЕ
   обновление списка читается `document.activeElement` и вызывается
   `active.focus()` — чтение activeElement + focus() форсируют синхронный
   стиль/лейаут посреди нашей пост-фазы. Проверка — фаза 1 (сделать focus
   восстановление условным: только если фокус был внутри перестроенных
   узлов).
4. **Подозреваемый №2 (create-путь)** — поэлементная сборка + слушатель на
   строку; лечение — делегирование (фаза 1) и компилятор (фаза 2, гейт).
5. `partial update`/`append`/`clear` — уже в классе Solid; регрессий там
   допускать нельзя.

## Пересмотр приоритетов фазы 1

Порядок по ожидаемому выигрышу: (1) фокус-restore в `each()` — вероятно,
съедает целый кадр на swap/remove/select; (2) делегирование событий —
create-путь и память; (3) аллокационная диета `h()` — по остаточному
принципу.

## Поправка после фазы 1: артефакт vsync и честная метрика

Проба no-op-клика показала: двойной rAF после ЛЮБОГО клика ≈ 16,6 мс на
обеих страницах (у Solid swap при выровненном замере — те же 16,7).
«Swap 3× хуже» из таблицы выше — артефакт фазы клика относительно
vsync-часов headless-Chromium, а не разница фреймворков: синхронный JS
swap — 0,7 мс у нас и у Solid. Харнесс дополнен колонкой **script ms**
(синхронное JS-время хендлера) — честная метрика для операций, влезающих
в кадр. Фикс focus()-restore в each() остаётся (гигиена: не форсировать
layout на каждом обновлении списка), но в headless-бенче он не виден.

## Раунд 2: аллокационная диета (одна сессия, машина «тёплая» — сравнивать по соотношениям)

| create many (10k), script ms | Solid | фактори | компилятор |
| ---------------------------- | ----- | ------- | ---------- |
| та же сессия                 | 30.45 | 76.5    | **47.8**   |
| соотношение к Solid          | 1×    | 2.5×    | **1.57×**  |

Сделано: ленивые коллекции Stream (холодный узел — ноль
Set/Map/Array-аллокаций; GC выпал из топа профиля), ленивые
cleanups/children в Scope, батч-вставка each() одним DocumentFragment на
серию свежих строк (each.update выпал из топа; paint 10k −10 мс), прямой
вызов компонентов в jsx-runtime (−3 аллокации на компонент),
прекомпьютнутые $$-ключи делегирования, Wire-first диспатч insertChild.

**Плато объявлено.** Абсолютные цифры между сессиями гуляют на ±10%
(тепловой дрейф headless-Chromium) — надёжны только соотношения внутри
одной сессии. По профилю остаток компилированного пути: ~30% —
нативные вызовы (cloneNode/createTextNode, у Solid те же), остальное —
тонко размазанная бухгалтерия подписок (ранги/targets/скоупы), т.е.
метаданные двух законов. Стоп-правило сработало: последние рычаги давали
<1.5 мс. Дальнейшее сжатие требует отказа от транзакционной семантики —
не делаем. Выигрыши раунда работают за пределами бенча: холодные
производные и скоупы больше не платят аллокациями за само существование.

## Раунд 3: слоты рёбер + selector() (одна сессия)

| create many (10k), script | Solid (createSelector) | Continuum (компилятор + selector) |
| ------------------------- | ---------------------- | --------------------------------- |
| script ms                 | 32.2                   | **43.25 (1.34×)**                 |

| select row, script | Solid | Continuum  |
| ------------------ | ----- | ---------- |
| script ms          | 0.30  | **0.10** ✓ |

Сделано: Edge-рекорды параллельным слотом (свап-удаление) вместо
listeners-Set + targets-Map + unlisten-замыканий — ranks ходят по тем же
рёбрам; postQ — плоские (fn, arg)-пары без замыкания на доставку;
`selector()` в ядре (один следящий процесс + ячейка на ключ, оба флипа в
одном моменте) — и наш бенч, и Solid-вариант переведены на селекторы
(krausest-идиома обоих).

µбенч рёбер (100k map+listen): create 78.6 → 70.3 мс, **teardown
103.5 → 17.8 мс (5.8×)** — свап-слоты против Set/Map/каскада; массовые
анмаунты (роуты, чурн списков) дешевеют кратно. Разрыв create с Solid:
2.4× (фактори до компилятора) → 1.57× (раунд 2) → **1.34×** — у «пола
модели» (~1.2–1.3×, транзакционные метаданные ребра). select теперь
БЫСТРЕЕ Solid. Относительный порядок двух выживших слушателей после
чужого удаления может измениться (как у слотов Solid) — эффекты внутри
момента по-прежнему в порядке доставки.

## Раунд 4: объектная диета — ПАРИТЕТ с Solid (одна сессия)

| create many (10k), script | Solid | Continuum (компилятор) |
| ------------------------- | ----- | ---------------------- |
| script ms                 | 32.2  | **33.9 (1.05×)**       |
| paint ms                  | 229   | **234**                |

| select row | Solid 0.30 | Continuum **0.10** ✓ |

Сделано: битфлаги (disposed/pinned → один int) и аудит полей Stream
(11 → 9: live interleaved, srcs — плоские пары без объектов); Cell —
класс с методами на прототипе вместо пачки замыканий; **инлайн первой
prioritized-записи транзакции** (куча — только со второй; моменты 500k:
65 → 41 мс, −36% на КАЖДЫЙ set любого приложения); buildScoped
возвращает Owner (минус объект + 2 замыкания на строку/dyn); textContent
fast-path для примитива в пустой родитель; **fused accum** (один узел
и одно ребро вместо пары accumE+hold — каждый счётчик вдвое дешевле).

µбенч (парные замеры одной сессии): рёбра create 108.7 → 60.2 мс,
teardown 25.6 → 13.1 мс; моменты 65.3 → 40.7 мс.

Путь create 10k: 2.4× → 1.56× → 1.34× → **1.05×**. «Пол модели»
оказался ниже оценки: транзакционные метаданные остались все — диета
срезала объектный вес вокруг них. Перф-историю можно закрывать: паритет
с Solid по созданию, преимущество на select, кратное — на teardown.

## Раунд 5: диета памяти — НИЖЕ Solid по heap и script (одна сессия)

Новый инструмент: `npm run bench:mem` (JSHeapUsedSize после полного GC
через CDP на чекпоинтах krausest; `performance.memory` квантуется и
непригоден).

| JSHeapUsedSize, MB | ready | create 1k | create 10k | clear после 10k |
| ------------------ | ----- | --------- | ---------- | --------------- |
| Continuum (до)     | 1.79  | 3.19      | 14.41      | **4.69** ← течь |
| Continuum (после)  | 1.79  | **2.92**  | **11.52**  | **1.97** ✓      |
| Solid              | 1.79  | 3.16      | 14.13      | 1.94            |
| vanilla            | 1.72  | 1.97      | 3.27       | 1.80            |

| create many (10k), script | Solid | Continuum (компилятор) |
| ------------------------- | ----- | ---------------------- |
| script ms                 | 39.85 | **34.05 (0.85×)** ✓    |

Сделано: **эвикция ячеек selector()** — ячейка без слушателей уходит из
Map (leaf-узлы получили onSleep при потере последнего наблюдателя);
10k очищенных строк удерживали 2.9 MB навсегда — это была настоящая
утечка, паритет с Solid по clear восстановлен. **Cell слит с Wire** —
один объект вместо пары, shared-функция вместо pull-замыкания на ячейку,
SourceCell с bound set/update (их передают отвязанными) вместо
Object.assign с тремя замыканиями и форком hidden class: wire() 568 →
320 Б (−44%). **POST-сентинел в Edge.t** — send_ постит юзер-хендлер в
фазу наблюдателей напрямую, без `(t,a) => t.post(h,a)`-обёртки на каждый
listen: 313 → 217 Б (−31%). **Плоские (stream, edge)-пары на Owner**
(observe_/unobserve_) — биндинг стоит два слота массива вместо двух
замыканий и слота в cleanups; instanceof Owner в bindWire заменён
дак-тайпингом, чтобы не тащить Owner в treeshaken-бандл компилятора
(+397 → +85 Б).

µбенч Node (Б/сущность): wire() 568 → 320, listen() 313 → 217,
wire().on 891 → 651, ячейка селектора 349 → 285, lift2 968 → 944.

Побочный эффект диеты: create 10k script теперь БЫСТРЕЕ Solid в той же
сессии (34.05 против 39.85). Бюджеты size-limit затянуты осознанно
(+50…85 Б на пакет: сентинел, эвикция, observe_).

## Раунд 6: heap-диета по снапшоту — −34% к Solid по памяти, ×2.8 к моментам

Новый инструмент: `npm run bench:heap` (CDP-снапшот кучи на чекпоинте,
агрегация self-size по конструкторам — КТО держит байты; сборка без
минификации ради имён классов).

| JSHeapUsedSize, MB | create 1k | create 10k | clear после 10k |
| ------------------ | --------- | ---------- | --------------- |
| Continuum (р. 5)   | 2.92      | 11.52      | 1.97            |
| Continuum (р. 6)   | **2.71**  | **9.36**   | 1.97            |
| Solid              | 3.16      | 14.13      | 1.94            |

| create many (10k), script | Solid | Continuum (компилятор) |
| ------------------------- | ----- | ---------------------- |
| script ms                 | 34.9  | **31.95 (0.92×)** ✓    |

Сделано по аудиту снапшота (массивы были крупнейшей JS-статьёй: 40k ×
~73 Б): **инлайн первого ребра Stream (`ob0`)** — у большинства узлов
ровно один наблюдатель, массив `obs` появляется только со второго
(снапшот: массивов 40k → 10k, −1.6 МБ); **`nodes: Node | Node[]`** —
одноэлементная строка не платит за массив; **`EachOwner.key`** — минус
10k Row-обёрток; **`disposed`/`mounted` → биты** Scope.flags. Транзакция:
ленивая куча, **плоский lastQ + кэш commit/prioritized-замыканий** на
узлах (Cell, hold, accum, once, distinct, lift2, selector — ноль свежих
замыканий на момент), **пул одной транзакции** (момент с исключением не
переиспользуется; идентичность моментов — через `t.id`, см. makeFire).

Находка профиля: `array.length = 0` при сбросе очередей — это
runtime-вызов V8, доминировавший в 500k-профиле; курсорные записи в
переиспользуемый массив (с зачисткой слотов при дрейне) убрали и его, и
аллокации: **5M set → 166 мс против ~460 у main (×2.8)**, мусор ~1 Б на
set (было ~238 Б). µбенч Node: map awake+listen 1170 → 990 Б; Stream/
wire() потяжелели на поле (88→96 / 320→336) — плата за ob0/sendFn,
перекрытая массивами. Бюджеты: frp 4.25 / dom 6.7 / std 3.76 /
router 6.44 / compiled 3.85 (+~250 Б кода за ветки ob0 и пул).
